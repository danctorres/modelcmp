# modelcmp keys

Every key and mouse action in the TUI. Press `?` in the TUI for the short list. The
[README](README.md) covers install and the basics, [REFERENCE.md](REFERENCE.md) the columns,
commands and JSON.

## General

| Key | Action |
|-----|--------|
| `?` | help. `/` keeps the lines that match |
| `esc` | back: closes an overlay, drops the highlight, clears the `/` filter, leaves `S`, then `F`, then `E`, then a task picked in recommend back to recommend |
| `qq` `^c` | quit. The first `q` asks, `^c` does not. From an open list too, unless something is being typed there, and any other key is back on the list |
| `r` | refresh data now |
| `UU` | upgrade modelcmp when the frame's bottom left says a newer version is available. The first `U` asks. It closes the TUI, runs `brew upgrade` on a Homebrew install or `cargo install` of the new release on a cargo one, and starts the new version. A binary installed by hand gets the release's page opened instead |
| `B` | benchmarks from Epoch AI (the default, no API key needed) or Artificial Analysis (needs an API key). The TUI's first start asks for Artificial Analysis's key, under the wordmark: `enter` saves it and starts on Artificial Analysis, `esc` skips it and starts on Epoch AI, ctrl+c quits, while a click beside the question does nothing. With a key already there it asks nothing and starts on Artificial Analysis. A click on `artificialanalysis.ai`, underlined in `B`'s list and in the key prompt, opens the page where a free key is made. Artificial Analysis asks for its API key when none is saved and `ARTIFICIAL_ANALYSIS_API_KEY` is not set, and again if it rejects the key. Picking it again while it is the source changes the saved key, which is kept in `aa_key` next to `user.json`, readable by you alone. Each source has its own cache and a refresh fills both, Artificial Analysis's only with its key, so switching needs no download. The headers of the columns with a source's values are in its colour, cyan for Epoch AI and yellow for Artificial Analysis, as its name on the bottom border, so `ECI` or `AAII` says which one Coding, Agentic, Reason and Value are from |
| `H` | your default harness: lists `any harness`, then the harnesses you have a model on, starting on yours. `enter` picks one, `esc` leaves it as it was, and `H harness` is a hint in the table's status bar. `x` starts on it and `Y` copies the id it takes, for a model it has, and `--cmd` and `--id` go by it when `--via` names none, after a favorite's own harness (`v` in `f`'s grid). It hides no model. Saved in `user.json`, as `modelcmp harness claude` sets it |

## Move

| Key | Action |
|-----|--------|
| `j` `k` | move the cursor: a faint grey fill between two bars `▌` `▐` in the accent colour, on which the row keeps its colours. The same in dropdowns and lists, on a model's column in compare and on a task's name or one of its tiers in recommend. A count repeats, as in `3j`. Past the last row back to the first. The arrow keys work as `h` `j` `k` `l`, `PgDn` `PgUp` move a page, `Home` `End` go to the top / bottom |
| `h` `l` | pick a column, scrolling the ones right of Dev. `‹` `›` mark columns off screen, `▲` `▼` on the left border rows above or below. In compare, pick a model for `o` `x` `y` `f` `e` `n`, with the same marks for models off screen. In recommend, pick a tier of the task, `low` `mid` `high`, whose model those keys and `space` act on. The task's name comes before its tiers, and those keys there, or on a tier with no model, say to pick one |
| `0` `_` `$` `w` `b` | first / last column. Next / previous group: names and release, prices, scores, what a run measured (a task's cost and speed), Via. In compare, `0` `_` `$` pick the first / last model, in recommend the task's name / its `high` tier |
| `gg` `G` `3gg` | top / bottom / row 3. A number before `gg` goes to that row, as `12gg` to row 12, in dropdowns and lists too |
| `(` `)` `^u` `^d` | half a page up / down, stopping at the first / last row as `PgUp` `PgDn` and the wheel do. Overlays and dropdowns mark lines off screen with the same `▲` `▼` |
| `]` `[` | move the cursor to the next / previous selected model, past the last back to the first. A count repeats, as in `2]`. In `f`'s grid and the dropdowns, the next / previous ticked entry |
| `}` `{` | move the cursor to the next / previous model you have access to, past the greyed `not available` rows `a` shows, wrapping as `]` `[` do |
| `v` | highlight a range of rows: move to extend it, then `space` `e` or `C` act on all of it (`C` compares just the range, which becomes the selection in place of the models selected before). `v` again or `esc` cancels |

## Filter and sort

| Key | Action |
|-----|--------|
| `s` | sort by the column. Again reverses |
| `/` | filter by name, developer, Via or note, words in any order (`anthropic opus`), a typo forgiven when nothing matches (`opsu`). `/` again starts a new search, `enter` keeps what is typed, `esc` while typing goes back to the search before it and `esc` in the table clears it. In compare it filters the rows, in the help its lines, and in a list like the theme panel its entries, `f`'s tasks by their name. What matched is underlined in yellow everywhere, with the yellow behind it on a selected row's solid fill |
| `>` `<` | minimum / maximum for the column, e.g. `>` `155` `enter` on Coding. Ctx in thousands of tokens, `>` `200` for 200k. Released as a date, `>` `2026-06` for June 2026 on, `<` `2026-06` up to the end of June |
| `d` | dropdown on the headers marked ▾: Dev, Price, the task scores and Via. `/` searches it, as in every list, `space` or `enter` toggles several, as `space` selects models, and the dropdown stays open until `esc`. Dev lists the developers' countries first, as `China` or `USA`, each showing every model of a developer from there, when Epoch AI knows where the developer is from. On Price, where one level applies, they pick it or drop it. On Coding, Agentic and Reason they pick one of the task's benchmarks, as `DeepSWE` with Epoch AI or `scicode` with Artificial Analysis, and the column shows its score, 0-100, under its name, blank for a model not tested on it, so `s` sorts by it and `>` `<` bound it. The first entry (`all` with Epoch AI, the task's own benchmark with Artificial Analysis), the picked one again, `c`, `B` or choosing a task in `R` is back to the task's score. The list says how many models each benchmark scored. The pick lasts until the TUI closes and leaves recommend and the command line alone. Via lists the harnesses, then `local`, the models your machine runs through ollama or llama.cpp, whoever else offers them too, `not local`, the others, and `↓ download`, the ones ollama or llama.cpp can download from their Hugging Face repo (`x`, `download and run`), most of them in `all` |
| `a` `A` | `a` is the `all` tab: all models, including ones you have no access to, greyed out with `not available` under Via. `A` is the `yours` tab, the models you have access to plus the selected ones you have not, which its `+2` counts, and either leaves `S` `F` `E`. With access to none, every model is shown and a line above the first says so |
| `\|` | the columns to show: a list of every column right of Dev, each with what it means, `✓` while it shows. `space` or `enter` toggles one and the list stays open until `esc` or `\|`, `/` searches it and `]` `[` go to the next / previous ticked one. Saved in `user.json`. The columns of the benchmark source not in use are listed when both sources are cached, and the command line prints every column whatever is picked here |
| `tab` `shift+tab` | next / previous tab of the line above the table, `yours A   all a   ✓ selected S   ★ favorites F   ✗ excluded E   recommend R   compare C   theme t   help ?`, each with its key: the models you have access to, all models, the selected, favorite or excluded only (as `S` `F` `E`), one at a time, and the panels recommend and compare, the theme list and the help, which a tab or a click on another leaves for it, as it does a model's details. Compare is greyed and skipped with fewer than 2 models selected. The tab on is bold in its colour inside a frame of its own, whose sides run down into the table's frame, open under it, as a browser's tab (a panel's, the panel a box of its own, stands on the frame, closed), and a thin line parts two that are off. One with nothing to show is greyed and skipped. A tab cut off a narrow terminal is a hint in the status bar instead, in a panel too, where only the panels' keys work. A click on `yours` or `all` shows it. A click on `✓` `★` `✗` turns it on or off as `S` `F` `E` do. Search, bounds and dropdowns still narrow the tab shown |
| `%` | Price with no input cached, as a one-off prompt, instead of the share it started with (an agent's 90%, or `--cache`). Again: back to that share. The top border on Price says which, and the hint shows on the price columns, or anywhere while no input is cached. Value, the cheapest provider and recommend follow it. `modelcmp --cache 50` starts the TUI with any other share |
| `c` | clear filters, bounds, task, `S`, `F` and `E`, and the selection stays |

## Selected ✓, favorite ★, excluded ✗

Selected models (`✓`) are your shortlist, kept until you deselect them, across restarts too. A favorite
(`★`) is your pick for a task, on that task's line in recommend while you have it and did not exclude it. An excluded model
(`✗`) is one you have but cannot use, so recommendations skip it.

| Key | Action |
|-----|--------|
| `space` | select the model: the shortlist you are deciding between, kept until you deselect it, across restarts too. Its grey `✓` turns light blue and its row gets a faint light-blue fill, on which it keeps its colours, with the `✓` in light blue and the name in bold. A click on the `✓` toggles it. With the `terminal` theme the fill is mixed from the terminal's background, which it is asked for at start. In a terminal that does not tell, or does not say it draws 24-bit colour (`COLORTERM` is `truecolor` or `24bit`, `TERM` names kitty, alacritty, ghostty, foot, wezterm or a `-direct` terminal, or it runs under WSL. Over `ssh`, which drops `COLORTERM`, set it on the remote), the fill is solid and the row black on it, the cursor is a reverse-video bar with colours off it, and a model not selected has a `☐` and one not excluded a `·`, as grey would not show |
| `f` | favorite the model for tasks, or for one tier of a task (`coding:low`, listed under the task), which `--tier` picks before the task's favorite. Every row has a `☆`, filled bold `★` for a favorite: with a task picked, that task's favorite in the task's colour, the colour of its name in recommend. With none, a gold `★` for the favorite of any task. `f` or a click on the `☆` opens a grid, a row per task and a box per column: `any` for the task and `low` `mid` `high` for its tiers, `✓` where the model is the favorite, `●` where another model is and `☐` where none is. Each row ends with what the task is about, and the line under the grid names what the box under the cursor holds. `j` `k` move between tasks and `h` `l` along a row's boxes, a count repeating. `space`, `enter` or a click ticks the box and the grid stays open until `esc`, a click on a task's name ticking its `any`. `]` `[` go to the next / previous task with a tick, past the last back to the first, a count repeating. The grid starts on the picked task, or the task under the cursor in recommend, on the box the model has there, else in recommend on the box of the cursor's tier, so `f` `enter` is for that tier alone, and with no task on the first box it has. Your own tasks follow the built-in ones, and the last entry, `+ new task`, takes the name of a new one, written right on the entry with the grid open (`Tool Dispatch` is saved as `tool-dispatch`), and then what it is about on the new task's row, which `enter` on nothing skips: it has that model, its tiers have boxes as a built-in task's (`tool-dispatch:low`) for a model of their own, its `★` and name have a colour no built-in task has, picked by its name, and it is gone once nothing of it is ticked. `r` on one of your own tasks writes another name on its row, starting from the one it has, and `a` what it is about, which the row and recommend show and agents pick the task by, over a built-in task that fits too. `enter` applies, `esc` leaves the row as it was, a name some task has already is said under the grid, and on a built-in task or one with nothing ticked both say why not. `v` on a ticked box lists the harnesses that have its model, as `x` does, after `any harness`, starting on the one it has: `enter` picks one and `esc` leaves it as it was, both back on the box in `f`'s grid, where the line under the grid shows it as `via claude`. `--id` then prints the id that harness takes. On a selected row `f` is for that row alone. A task has one favorite, so with several models highlighted `f` says it takes one, and a click on a `☆` is always for its row alone. The status bar names the tasks the model under the cursor is the favorite for. `--tier` picks the model even off the price frontier, and recommend shows it greyed there, marked `not recommended` under the grid |
| `e` | exclude the model: you have it but cannot use it. It stays in the table, greyed out as a model you have no access to is, but recommendations (`R` and `--task`) skip it. A greyed row keeps only the colours of its `✓`, `★` and `✗`: best and worst are those of the other rows, and compare greys its column the same way. Every row has a grey `✗`, red when excluded, and `e` or a click on it toggles the exclusion of that row alone, even on a selected one |
| `V` | highlight the selected models shown, as `v` highlights a range: `Ve` excludes them all, or unexcludes them when all are excluded, and `esc` cancels. A hint in the status bar while one is selected |
| `u` | deselect every model. A hint in the status bar while one is selected |
| `DD` | unfavorite every model, for every task and tier, tasks of your own included, which go with their models. The first `D` asks, and any other key cancels. A hint in the status bar in `F` |
| `XX` | unexclude every model. The first `X` asks, and any other key cancels. A hint in the status bar in `E` |
| `S` | selected models only. `S` again or `esc`: every model |
| `F` | favorite models only, the rows with a `★` (the picked task's favorite when a task is picked), the ones you have no access to too, from `yours` as from `all`. `F` again or `esc`: every model |
| `E` | excluded models only, the rows with a red `✗`, the ones you have no access to too, from `yours` as from `all`. `E` again or `esc`: every model |

## Model under the cursor

| Key | Action |
|-----|--------|
| `n` | note for the model. `recommend --json` gives it to agents, who use it to choose between models |
| `y` `Y` | copy the model name / the model id: the one your default harness (`H`) takes when it has the model, else `provider/model`, as opencode takes it, or pi or omp when only they have the model, or the tag `ollama run` takes, or the repo (`-hf`) or file (`-m`) `llama-cli` takes, for one only your machine runs |
| `o` | open the model on models.dev, epoch.ai, artificialanalysis.ai, openrouter.ai or huggingface.co, whichever have a page for it, and on arena.ai, its agent leaderboard, when it has an Arena score. Lists them to pick from, even when only one does |
| `x` | open a harness on the model in a new terminal (Windows Terminal under WSL, else `$TERMINAL`, else `x-terminal-emulator`). Lists the harnesses that have it to pick from, even when only one does, starting on your default one (`H`). For a model with a repo on Hugging Face that ollama or llama.cpp does not have here, the list ends with `download and run`, which is `modelcmp get`, followed by the size of the download, as `(2.5 GB)`, which Hugging Face is asked for once the cursor rests, for the model under it and the local ones on screen, and which is kept for the next runs, while a model Hugging Face has no GGUF copy of says so there and has no such entry afterwards, until a refresh (`r`) or a week later, and with `install, download and run` when you have neither. The details of a model say that size too, also of one a runner here has, as the size of its GGUF copy on Hugging Face. A model `x` can download has a `↓` under Via, in details and in compare, followed by the size once known, and in place of `not available` when a download is the only way to it |

## Panels

| Key | Action |
|-----|--------|
| `enter` | details: every benchmark, price per provider. `space` `f` `e` `n` `o` `x` `y` act on the model there too |
| `C` | compare 2+ selected models: cheapest, best coder, best value. `h` `l` pick a model, and the table's cursor follows it, `enter` shows its details, which `esc` leaves back to compare. `C` again or `esc` closes it |
| `R` | recommend: a grid with a row per task and a box for each tier, `low` `mid` `high`, holding the model `--tier` picks, as `name $price (score)`: your favorite for the tier, else for the task, with a `★`, else the cheapest model that scores enough, the best for `high`. A name is cut from its start to the room its box has, as `…Opus 5.5`, and `value`, a rank with no tiers to tell apart, has one box for its pick unless you favorite a model for one of its tiers. A box with no model shows `-`, where `enter` and the model keys say it has none. Under the grid, and kept there while the rows scroll in a terminal too short for them all, what the cursor's task measures, when to use it and the model of the box it is on in full, which says `not recommended` for a favorite off the price frontier. Its first line says which models it ranks, as `among: ● yours · ○ all · ○ ✓ selected · ○ ★ favorites`: the one in use has the filled dot `●` and is bold in its tab's colour, with `(filtered)` while a search, a dropdown or a bound narrows them too, and `E` narrows none. With `all` it ranks the models you have no access to too, each greyed, as its row in the table, and `not available` under the grid. The cursor starts on that line, and `k` from the first task or `gg` goes back to it. There `h` `l` move over the ones with something to show and `enter`, `space` or a click picks one, the panel staying open and the table on that tab after it. A tab's key leaves recommend for the tab, as a click on the tab does. `j` `k` move between tasks, staying on the name or on the tier, and `h` `l` along a task's row to a tier, whose model `space` `o` `x` `y` `f` `e` `n` act on and the table's cursor follows, so `R` again or `esc` lands on it. `enter` on a model opens its details, and on a task's name shows its price frontier in the table, the best model at each price level, best first, each row cheaper and scoring lower. Your own tasks come last, each tier with the model you gave it, else the task's, and `enter` on one's name goes to its cheapest model in the table |
| `t` | theme panel: `j` `k` preview, `/` searches, `enter` saves, `esc` or `t` closes. `terminal` (its own colours, the default), then the dark `gruvbox`, `nord`, `catppuccin`, `dracula`, `tokyonight`, `kanagawa`, `monokai`, `github`, `solarized`, `synthwave` and `cyberpunk`, the light `github-light`, `sepia` and `catppuccin-light`, and the retro `amber`, `phosphor`, `c64` and `gameboy`. Saved in `user.json`. A theme sets the 16 terminal colours, the text colour and 7 to 14 colours for developers, each of which has to read on that theme's background and stay apart from the others. Every theme paints its own background, so a dark one stays dark on a light terminal. Only `terminal` keeps a transparent background, but for a selected row's fill and the cursor's |

## Input and mouse

| Key | Action |
|-----|--------|
| typing | `←` `→` `^b` `^f` move, `^a` `^e` `Home` `End` to the start / end, `alt-b` `alt-f` `^←` `^→` `alt-←` `alt-→` by word. `↓` `↑` move the table's cursor under a `/` search. `^w` `alt-d` delete a word, `^u` `^k` to the start / end. A paste is typed as one line, and with nothing being typed it only says there is nothing to paste into |
| mouse | click a row to highlight it. A double click opens what its cell shows: the name or developer the details, a harness in Via that harness, as `x` does, and a number its page in the browser, which is models.dev for a price, the context or the release date (the model's page, else that of the provider you'd pay), the source that measures it for the others, which is the one in use for the index to Value, Epoch AI for $task and Tok/task, Artificial Analysis for Tok/s and TTFT, the other source for its index, and arena.ai's agent leaderboard for Arena. A note opens to be written, as `n` does, even when empty, and a click anywhere leaves it, as `esc` does. Any other empty cell opens nothing, nor does a number on a site with no page for the model. Ctrl click adds or removes it from the highlight, shift click or a drag across rows highlights a range, a plain click drops the highlight, right click selects it, a click on its `✓` toggles the selection, on its `☆` picks its tasks, on its `✗` excludes it. A click on a tab shows it, `✓` `★` `✗` on or off as `S` `F` `E`, on the `#` header goes to the first row. A header sorts, its ▾ opens the dropdown, where clicks toggle entries until a click elsewhere. A click on a key hint in the status bar presses that key, when the hint names a single key. In compare and recommend a click on a model moves the cursor to it, in recommend one on a tier's box to that tier and one elsewhere on a task's row to its name, a double click does what `enter` does there and a right click in recommend what `space` does. A click outside an open panel (keys, details, compare, recommend) closes it, as `esc` does. The wheel scrolls, sideways (or shift+wheel) moves the column, or the model in compare and recommend |
